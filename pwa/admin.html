Duels
Annuler un duel rembourse intégralement les deux joueurs (mise recréditée sur leur solde disponible) sans commission — utile pour un salon resté coincé ou un abus signalé en dehors du circuit litige normal. Un duel de tournoi ne peut pas être annulé isolément (mises mutualisées : passe par l'annulation du tournoi entier). Un duel déjà terminé ou déjà annulé ne peut plus l'être.

Configuration paiement (Wave)
Lien Wave fixe utilisé pour tous les dépôts. Le joueur saisit le numéro avec lequel il va payer, puis un admin valide manuellement le dépôt depuis Telegram une fois le paiement vérifié sur le compte Wave (mêmes boutons ✅/❌ que l'arbitrage des duels).
Wave Checkout via API (inactif)
Ancien mode (clé API Wave Business + webhook automatique) — non utilisé par les dépôts actuellement (cf. lien fixe ci-dessus). Gardé au cas où on voudrait le réactiver plus tard.

🌊 Wave Monitor — validation automatique des dépôts
Se connecte au compte Wave Business pour détecter automatiquement les paiements reçus et créditer les dépôts en attente (sans attendre un clic admin sur Telegram). La validation manuelle Telegram reste disponible en secours si un paiement n'est pas reconnu automatiquement.

Connexion au compte Wave
Étape 1 : vérifie le PIN et envoie un code par SMS au numéro Wave Business ci-dessus.
Alternative : connexion via navigateur distant
Au lieu de saisir le PIN Wave Business ci-dessus, connecte-toi directement sur la vraie page Wave Business ci-dessous (PIN + code SMS gérés par Wave lui-même) — le serveur récupère automatiquement les cookies de session dès que la connexion réussit.

⚠️ Nécessite Chromium installé sur le serveur (Playwright) — plus installé automatiquement par npm install depuis ce changement, pour ne pas alourdir l'hébergeur. Si tu captures la session depuis VS Code en local (recommandé, cf. WAVE_MONITOR_CHANGES.md), ignore complètement cette section.

Configuration Email (SMTP)
Le code OTP d'inscription est envoyé par email en plus du SMS. L'adresse email est obligatoire à l'inscription : si le SMS échoue (opérateur, numéro invalide…), l'email suffit à valider le compte. Tant que ces champs sont vides, l'email est seulement écrit dans les logs du serveur (mode dev).
Avec Gmail, il faut un « mot de passe d'application » (le mot de passe du compte est refusé).
Doit généralement correspondre à l'utilisateur SMTP, sinon les messages partent en spam.
Enregistre d'abord la configuration — le test utilise les valeurs déjà en base.
